## Как открыть и повторить

Python 3.11+; проверено на Python 3.13 и Milvus 2.6.23.

```bash
python -m pip install -r requirements.txt
python -m unittest -v
```

Откройте `homework02.ipynb`. При `RECOMPUTE = False` он показывает сохранённые результаты, не требует ключа и не обращается к моделям или Milvus. Для нового эксперимента:

```bash
cp .env.example .env
# Заполните OPENROUTER_API_KEY в .env.
docker compose --profile ui up -d
python run_experiments.py retrieval
python run_experiments.py answers
python run_experiments.py memory
```

Сначала посмотрите результаты поиска, затем запускайте ответы. Конфигурации уже выполнены: `answers` переиспользует существующие строки JSONL. Для нового независимого замера сохраните старую папку `results`, создайте пустую и снова выполните три этапа; кэш эмбеддингов оставьте. Не запускайте этапы одновременно. Ограничение `RUN_BUDGET_USD` относится к одному процессу; параллельные запросы могут немного превысить порог.

После нового замера нужен новый просмотр ответов по смыслу. Старые правки `manual_review.json` нельзя переносить на другие ответы. Ячейки ноутбука показывают сохранённый отчёт; старые текстовые выводы в нём и этом README относятся к данному запуску.

`homework02.py` — функции, `run_experiments.py` — измерения, `test_homework02.py` — шесть проверок без API. В `results` — ответы, стоимость, таблицы и графики. `.env`, журнал диалога, факты пользователя и данные базы исключены из git. Для памяти используются вымышленные сведения о Лене.

## Корпус и нарезка

PDF извлечён через pypdf; оставлена 931 страница с текстом длиной не меньше 80 символов. Готовый корпус включён в `data/corpus.jsonl`, поэтому для запуска сам PDF не нужен. Повторить извлечение можно через `python prepare_corpus.py путь/к/книге.pdf`. Имя файла и SHA-256 оригинала — в `data/provenance.json`.

Две нарезки:

- **Страница PDF:** 931 фрагмент. Граница совпадает со страницей, поэтому сохраняются соседний текст и удобная ссылка на источник. Однако это не всегда граница смысла.
- **400 символов:** 4656 фрагментов, без overlap. Простой семинарский вариант, который может разрезать предложение.

У каждого фрагмента есть файл, номер страницы PDF и `section`. Печатный номер может отличаться: в отчёте и ответах используются именно страницы PDF. Поле `url` пустое, потому что источник локальный.

30 вопросов с коротким ответом и цитатой — в `data/questions.jsonl`. Они относятся к вводной прозе на 12 страницах, хотя в поиске участвует вся книга. Это узкий тест, а не оценка работы со всеми разделами учебника. Ещё 10 вопросов без ответа — в `data/unanswerable.jsonl`: современные данные, личные результаты пользователя и статистика, которой нет в книге. Такие отрицательные примеры сравнительно простые.

## Поиск

Эмбеддинги: `openai/text-embedding-3-small`, 512 измерений. Ключ кэша включает модель, размерность и текст. Уже оплаченные векторы импортированы из семинара. Повторное извлечение векторов корпуса не требуется; новые запросы агента дополняют кэш.

Recall считается по 30 ответимым вопросам. Верный фрагмент: тот же документ и страница PDF, есть короткий ответ и не менее половины слов цитаты после нормализации. Это приближённая семинарская проверка; она может не распознать полезное повторение факта на другой странице.

![Recall](results/recall.png)

Кривые получены **точным поиском NumPy**. При k=5 страницы дают 70%, блоки — 90%. Выбраны блоки и k=5: при k=10 появляется лишь один дополнительный ответ, 28 вместо 27. Выбор сделан на этом же наборе, без отдельной отложенной выборки.

| Нарезка | Поиск | Recall@1 | Recall@5 | Recall@10 |
| --- | --- | --- | --- | --- |
| страницы | вектор | 40.0% | 70.0% | 80.0% |
| страницы | слова | 53.3% | 80.0% | 83.3% |
| страницы | гибрид RRF | 53.3% | 83.3% | 86.7% |
| 400 символов | вектор | 56.7% | 90.0% | 93.3% |
| 400 символов | слова | 53.3% | 73.3% | 76.7% |
| 400 символов | гибрид RRF | 60.0% | 90.0% | 90.0% |

По словам используется сумма IDF совпавших слов, без морфологии. RRF объединяет первые 20 результатов со сглаживанием 60. Для блоков гибрид не улучшил Recall@5, поэтому в ответах используется векторный поиск.

В Milvus хранится 4656 фрагментов с метаданными. Фильтр `pdf_page <= 30` ограничивает поиск вводной частью. Важная проверка: с семинарским `AUTOINDEX` фактический Recall Milvus при k=1,3,5,10 равен **53.3%, 76.7%, 80.0%, 86.7%**. То есть реальные ответы опираются на менее точную выдачу, чем исходная кривая NumPy. Это один из путей улучшения: проверить настройки приближённого индекса или точный индекс на таком небольшом корпусе. Проверка сохранена в `results/milvus.json`.

## Два типа ошибок

Лучшая конфигурация — дешёвый агент с базой, 25/30. Его пять ошибок относятся к случаю «эталон не найден» по принятому критерию. Ошибок «нашёл, но ответил неверно» у него в этом прогоне нет. Поэтому второй пример ниже взят **из дешёвого RAG**, а не приписан лучшей конфигурации.

**Поиск не нашёл — вопрос 23, агент.** Нужное название главы — «Шпаргалки», цитата на странице PDF 27. Агент получил фрагменты с формулами, оглавлением и напоминаниями, но не нужный фрагмент. Ответил «Справочные материалы, стр. 4». Нужны более точный поиск и проверка наличия названия в найденном тексте; при недостатке данных лучше отказ. В точном поиске нужный кусок находится, поэтому настройки индекса здесь особенно важны.

**Нашёл, но ответ неверный — вопрос 3, RAG.** В контексте на странице PDF 10 есть фраза о заданиях, традиционно дававшихся на вступительных экзаменах, и отдельно сказано, что в книге нет заданий из вариантов ЕГЭ прошлых лет. Модель ответила «на вступительных экзаменах и ЕГЭ»: смешала происхождение задач с целью подготовки. Поиск здесь сделал свою работу. Исправлять нужно генерацию: просить точный ответ на заданный вопрос и проверять его по цитате. Полный пример сохранён в `results/failure_examples.json`.

**Отдельный провал — формулы.** В начале урока 2 pypdf превращает математическую запись в фрагменты вроде `tg®±tg у` и `s h i t`, а решение обрывается на границе страницы: «перенеся все в левую» / «часть, получим». Простая смена размера фрагмента не восстановит испорченные символы. Нужен разбор формул или OCR; в этой работе задача ограничена читаемой прозой.

## Память

Журнал хранит сессию, время, роль и текст, но в контекст не загружается. В конце сессии GPT-4o mini выделяет устойчивые факты. Они лежат в отдельной коллекции Milvus. Новый список фактов заменяет старый, поэтому Казань и Пермь не остаются одновременно текущим городом.

Во второй сессии без истории первой агент вспомнил имя Лены и цель подготовки. Город в первый ответ не попал: поиск вернул только три факта и пропустил `city`. Это ограничение top-k памяти, а не потеря записи. После сообщения о переезде в базе проверен факт `city: Пермь`; старой Казани там нет. В отдельном вопросе бенчмарка город был найден правильно.

![Токены](results/memory_tokens.png)

| Контекст | Входных токенов | USD за 10 реплик |
| --- | --- | --- |
| full | 12112 | 0.001960 |
| window | 10149 | 0.002002 |

`full` — вся история, включая первую сессию и изменение города; `window` — четыре последних сообщения и три найденных факта. Десять пользовательских реплик одинаковы, модель одна. Суммируются все шаги агента и новые эмбеддинги поиска памяти; поэтому кривая не обязана расти монотонно. Извлечение фактов в конце двух сессий стоило ещё $0.000185; это общий подготовительный расход, показанный отдельно.

Входных токенов стало примерно на 16.2% меньше. Но в этом коротком прогоне окно с фактами стоило чуть дороже. Ответы и число вызовов инструмента различались; экономию денег на основании одного такого диалога обещать нельзя.

Проверки без модели: пустая память, найденный факт, заменённый факт; для инструмента — результат, пустая выдача, фильтр. В них подменены Milvus и эмбеддинги. Настоящая база отдельно проверена демонстрацией и поиском обновлённого факта.

## Вывод

На этом наборе агент с дешёвой моделью оказался точнее сильной модели без источников: 83.3% против 40%. Цена верного ответа ниже примерно в 11.5 раза. Причина — доступ к нужному тексту, а не более сильная модель. Дешёвая модель без базы ещё дешевле по этой метрике, но отвечает верно лишь на 5 из 30 вопросов: одной цены без качества недостаточно.

Это не прямое сравнение с прошлой неделей: корпус сменился, живого поиска по нему не было. Для памяти снизились входные токены, но не итоговая цена. Все записанные вызовы текущего эксперимента вместе стоили **$0.194535**. Реальные ограничения — небольшой тематический тест, повреждённые формулы, качество индекса и приближённая оценка ответов.
